# ข้อมูลสำหรับวางแผนย้ายระบบส่งแผนการสอนไป Supabase

เตรียมโดย Claude ตามที่ครูเต้ยขอ (5 ต.ค. 2569) สำหรับพี่กันใช้วิเคราะห์โค้ดและทำแผน

## 1. ทำไมต้องย้าย

- ระบบตอนนี้เป็นโปรแกรม Node.js ที่ต้องเปิดค้างบนเครื่องแม่ตลอดเวลา
- โรงเรียนไม่มีคอมที่เปิดทิ้งไว้ได้ และ ผอ. ไม่อนุญาตให้เปิดคอมทิ้งไว้
- ครูเต้ยไม่อยากมีค่าเช่าเครื่องรายเดือน
- อยากเก็บไฟล์แผนและคู่มือใน Google Drive ของโรงเรียน (Google Education 100 GB) แยกโฟลเดอร์ ภาคเรียน / กลุ่มสาระ / ชื่อครู / คู่มือรายวิชา หรือ แผนการจัดการเรียนรู้
- ทางที่เลือก: GitHub + Supabase + Google Drive
- **กำหนดใช้จริง: เปิดรับงานภาค 2/2569 ประมาณต้นพฤศจิกายน 2569**

## 3. ระบบปัจจุบัน

- Node.js 22.13 ขึ้นไป, Express 5, EJS (หน้าเว็บสร้างฝั่งเซิร์ฟเวอร์), SQLite ที่มากับ Node (`node:sqlite` แบบ synchronous)
- อัปโหลดไฟล์ด้วย multer เก็บใน `data/uploads`, รวม PDF ด้วย pdf-lib, แปลง Word ด้วย LibreOffice (`child_process`)
- ขนาด: 90 เส้นทาง, 52 หน้า EJS, เรียกฐานข้อมูล 209 จุด (`q.get/all/run/tx`), คำสั่งเฉพาะ SQLite 18 จุด, trigger 3 ตัว
- โค้ดฝั่งเซิร์ฟเวอร์ประมาณ 5,200 บรรทัด, หน้าเว็บ 3,200 บรรทัด, ตัวทดสอบ 1,700 บรรทัด (49 ข้อ ผ่านทั้งหมด `npm test`)

**ไฟล์สำคัญ**

| ไฟล์ | หน้าที่ |

| `src/workflow.js` | กฎส่งต่อ ข้ามระดับ ส่งกลับ ให้คะแนน ลงนามงานตัวเอง ผู้ดูแลดำเนินการแทน |

| `src/routes/work.js` | ส่งแผนและคู่มือ บันทึกหลังแผน เปิดไฟล์ พิมพ์เอกสาร ลงนาม |

## 4. ระบบที่ติดเมื่อย้ายไป Supabase

ถ้าเอาโค้ดเดิมขึ้นไปตรง ๆ ใช้ไม่ได้ทุกระบบ เพราะไม่มีที่ให้ Express ทำงานค้าง (Edge Functions ทำงานทีละคำขอ และเท่าที่ทราบไม่ส่ง HTML จากโดเมน supabase.co)

**กลุ่ม ก: ต้องรื้อ และต้องเสร็จพร้อมกันทั้ง 4 ส่วนระบบถึงเริ่มใช้ได้**
1. หน้าเว็บ 52 หน้า (EJS ฝั่งเซิร์ฟเวอร์) ต้องย้ายไปเป็นหน้าเว็บฝั่งเบราว์เซอร์ วางบน GitHub Pages หรือ Cloudflare Pages (GitHub Pages ฟรีต้องเป็น repo Public เท่าที่ทราบ Cloudflare Pages ใช้ repo Private ได้)
2. ฐานข้อมูล SQLite เป็น PostgreSQL: แปลงตาราง คำสั่งเฉพาะ SQLite (group_concat, randomblob, INSERT OR IGNORE/REPLACE, PRAGMA, VACUUM INTO, lastInsertRowid) trigger 3 ตัว และทุกจุดต้องเป็น async
3. สิทธิ์ข้อมูล: เบราว์เซอร์คุยกับฐานข้อมูลตรง ต้องมี RLS ทุกตาราง **จุดเสี่ยงที่สุด** ห้ามให้ครูแก้คะแนน ลายเซ็น สถานะ หรือ audit_log เองได้
4. กฎ workflow ใน `src/workflow.js` ต้องอยู่ฝั่งที่ครูแก้ไม่ได้ เช่น Postgres function (SECURITY DEFINER) หรือ Edge Function

**กลุ่ม ข: ติด แต่มีทางอ้อม**
5. เข้าสู่ระบบ: Supabase Auth ใช้อีเมลหรือเบอร์โทร และรหัสขั้นต่ำ 6 ตัว (เท่าที่ทราบ) แต่ระบบเราให้ครูเลือกชื่อแล้วใส่รหัสตัวเลข 4 หลัก ต้องเขียน auth เอง หรือตกลงเปลี่ยนกติกา
6. ไฟล์ถึง 100 MB: Supabase Storage ฟรีประมาณ 1 GB และไฟล์ละประมาณ 50 MB จึงควรส่งตรงเข้า Google Drive ของโรงเรียน (resumable upload)
7. แปลง Word: **ทำแบบเดิมไม่ได้** ไม่มี LibreOffice ทางเลือกคือให้ Google Drive แปลง (ไม่มีฟอนต์ TH SarabunPSK หน้าเพี้ยน) หรือตัดฟังก์ชันนี้แล้วสอนครูบันทึกเป็น PDF เอง
8. LINE สรุปทุกเช้า: ใช้ pg_cron + Edge Function
9. สำรองข้อมูล: แบบฟรีไม่สำรองอัตโนมัติ (เท่าที่ทราบ) ต้องทำเอง เช่น ส่งออกเข้า Google Drive ทุกคืน
10. แบบฟรีหยุดเองถ้าไม่มีคนใช้ 1 สัปดาห์

**กลุ่ม ค: ย้ายได้ไม่ยาก**
11. รวม PDF (pdf-lib ใช้ในเบราว์เซอร์ได้ แต่มือถือเก่ากับไฟล์ใหญ่อาจช้า)
12. หน้าพิมพ์บันทึกข้อความ แบบประเมิน QR Code (ไลบรารี qrcode ใช้ในเบราว์เซอร์ได้)
13. คัดลอกไป Google Drive (ตอนนี้ใช้โปรแกรม Drive for desktop ต้องเปลี่ยนเป็น Drive API)
14. ตัวทดสอบ 49 ข้อต้องเขียนใหม่

**ที่ด้อยลงจริงสำหรับผู้ใช้:** รวม PDF บนมือถือเก่า และระบบหยุดเองเมื่อไม่มีคนใช้ 1 สัปดาห์ ที่เหลือทำให้ผลเหมือนเดิมได้แต่ต้องเขียนเพิ่ม

## 5. กติกาที่ต้องคงไว้ (รายละเอียดใน CLAUDE.md)

- คู่มือรายวิชาส่งทุกวิชาที่สอน แผนส่งเฉพาะวิชาหลัก (`users.plan_quota` ปกติ 1) PDF ไฟล์เดียว วิชากิจกรรม (รหัสขึ้นต้น ก) ไม่ต้องส่ง
- ลงนาม 5 ระดับ: หัวหน้ากลุ่มสาระ (ให้คะแนน 20 ข้อ เต็ม 100) > หัวหน้างานส่งเสริมฯ > หัวหน้าวิชาการ > รอง ผอ. > ผอ. ส่วนบันทึกหลังแผนมี 3 ระดับ
- ระดับคุณภาพ: 90 ดีมาก, 70 ดี, 50 ปานกลาง, 30 พอใช้, ต่ำกว่านั้นปรับปรุง
- ผู้ตรวจลงนามงานตัวเองได้ (สวิตช์ selfsign)
- ผู้ดูแลดำเนินการแทนได้ทุกขั้น แต่บันทึกเป็น action override และลง audit_log เสมอ ห้ามใส่ลายเซ็นคนอื่นแทน ห้ามดำเนินการแทนในงานของตัวเอง
- audit_log เพิ่มได้อย่างเดียว แก้หรือลบไม่ได้ (ปัจจุบันใช้ trigger)
- ผอ. และรอง ผอ. เป็นผู้ดูแลระบบไม่ได้
- รหัสผ่านดูย้อนไม่ได้ ตั้งใหม่ได้อย่างเดียว ครูใช้รหัส 4 หลักได้ แต่ผู้ดูแล ผอ. รอง ผอ. ต้อง 6 ตัวขึ้นไป
- ทุกฟังก์ชันใหม่ต้องมีสวิตช์เปิดปิดในหน้าฟังก์ชันเสริม
- ข้อความบนหน้าจอเป็นภาษาไทย ไม่ใช้ขีดยาว จุดคั่น จุดไข่ปลา เครื่องหมายคำถาม ทุกปุ่มที่เปลี่ยนข้อมูลมีป๊อปถามยืนยัน
- ใช้ได้ทั้ง Windows Mac Chrome Edge Safari และมือถือ iPhone iPad
- หน้าพิมพ์ต้องตรงไฟล์ Word ของโรงเรียน (TH SarabunPSK ขอบและขนาดตาม CLAUDE.md จบใน 1 หน้า)
- ห้ามใส่ชื่อจริงครูหรือผู้บริหารในโค้ด ข้อมูลทดลอง หรือตัวทดสอบ
- ครูหลายท่านไม่คุ้นเคยกับเทคโนโลยี ต้องง่ายที่สุด

## 6. คำถามที่แผนควรตอบ

1. หน้าเว็บจะวางที่ไหน (GitHub Pages ต้อง Public / Cloudflare Pages)
2. เข้าสู่ระบบแบบไหน และรักษารหัส 4 หลักกับการเลือกชื่อได้อย่างไร
3. กฎ workflow และ RLS จะเขียนแบบไหน ทดสอบอย่างไรว่าครูแก้คะแนนหรือลายเซ็นเองไม่ได้
4. ไฟล์จะส่งเข้า Google Drive อย่างไร (ใช้บัญชีโรงเรียน, OAuth, resumable upload, สร้างโฟลเดอร์อัตโนมัติ) และผู้ตรวจเปิดอ่านไฟล์อย่างไร
5. ตัวแปลง Word จะทำอย่างไร หรือตัดออก
6. จัดการเรื่องระบบหยุดเองหลังไม่มีคนใช้ 1 สัปดาห์อย่างไร
7. สำรองข้อมูลอย่างไร
8. ลำดับงานและเวลา ทันต้นพฤศจิกายนไหม ถ้าไม่ทัน เทอมนี้จะใช้อะไรแทน
